# DART 재무실적 조회 에이전트

KOSPI·KOSDAQ 상장기업의 매출액 / 영업이익 / 당기순이익을 OpenDART 정기공시에서 추출·계산하는 웹 에이전트입니다.
(업무지시서 기준 3개 화면: 종목 검색·조건 설정 → 결과 → 분기별 상세)

## 실행
**로컬**: `python server.py` → http://localhost:8000 (Python 3.9+, 추가 패키지 없음, API 키 불필요)

**웹 배포** (Docker): 이 폴더를 GitHub에 올리고 Render / Fly.io / Railway 등에서 Docker 서비스로 생성하면 됩니다
(`render.yaml`, `Dockerfile` 포함). 환경변수:
- `DATA_SOURCE=web` (기본) 공시원문 스크래핑 / `api` OpenDART API(키 `DART_API_KEY` 필요)
- `APP_PASSWORD` 설정 시 접속 비밀번호(아이디는 아무 값) — **공개 배포 시 반드시 설정하세요**
- `HOST`, `PORT` 는 호스팅 환경에 맞게 자동/수동 지정

**점검**: `python diagnose.py 005930` — KRX 목록 → 공시검색 → 원문 파싱을 단계별로 확인합니다.
테스트: `python -m unittest discover -s tests -v`

## 원문 파싱 방식 (스크래핑 모드)
1. DART 공시검색으로 사업·반기·분기보고서 목록 확보 → 접수번호별로 원문(`main.do`) 열람
2. 목차(node 정의 또는 `viewDoc` 링크)에서 `연결재무제표`/`재무제표` 항목을 열람. 목차를 못 읽으면 모든 목차 항목 → 그래도 안 되면 `dcmNo`로 `eleId`를 순회
3. 본문 표 제목이 `연결 손익계산서`·`연결 포괄손익계산서`이면 연결, `손익계산서`·`포괄손익계산서`이면 개별로 분류(표 제목 기준)
4. 매출·영업이익·당기순이익 행이 모두 있는 표만 손익계산서로 인정(주석의 부문정보 표 제외), `(단위: …)`를 읽어 원 단위로 환산
5. 한 보고서를 읽지 못해도 해당 분기만 `검증 필요`로 표시하고 나머지는 계속 처리. 실패 시 진단 정보와 원본 HTML(`data/debug/`)을 남김

## 연결 당기순이익 추출 순서
연결 분기/연도는 다음 순서로 찾고, 대체 항목을 쓰면 화면(결과 셀 `대체기준` 태그, 상세조회 `대체` 표시·사유·주석)과 엑셀에 표시합니다.
1. 지배기업 소유주 귀속 당기순이익 → 2. 연결 당기순이익 전체(대체) → 3. 지배기업 소유주 귀속 총포괄이익(대체)

`당기순이익의 귀속` / `총포괄이익의 귀속` 머리글을 따라가며, 이름이 같은 `지배기업 소유주지분` 행이 어느 쪽 귀속인지 판정합니다(판정 불가 시 사용 안 함).
누적금액 차감(2·3·4분기)은 **같은 추출 단계끼리만** 수행하고, 단계가 다르면 `검증 필요`로 둡니다. 개별 분기는 항상 개별 당기순이익입니다.

## 엑셀 내보내기
결과 화면의 **엑셀로 내보내기** 버튼 → 시트 3개(재무실적 결과 / 분기별 상세 / 계산과정), 금액은 원 단위 숫자.

## 금액 단위
결과는 항상 **원 단위**입니다. 공시원문의 `(단위 : 백만원)` / `(단위 : 천원)` 표기를 읽어 숫자 뒤에 `000,000` / `000`을 붙인 값
(=×1,000,000 / ×1,000)으로 환산하며, 상세 화면에 "공시단위 → 원 환산"을 표시합니다. 단위 표기를 찾지 못한 재무제표는 추정하지 않고 `검증 필요`로 처리합니다.
백만원·천원 공시 기업은 원 단위 값의 하위 자릿수가 모두 0이며, 합계·차감 결과도 같은 정밀도입니다.

## 구조
| 파일 | 역할 |
|---|---|
| `dart_web.py` | **기본 데이터 소스**: KRX KIND 목록 + DART 공시검색 + 뷰어 원문 HTML 파싱 |
| `dart.py` | SQLite 저장(Raw·Quarterly·TTM·Basis History) + (선택) OpenDART API 클라이언트 |
| `engine.py` | 분기별 연결·개별 판정, 분기 실적 추출·차감, TTM 합산, 변경 감지·주석 |
| `server.py` | 검색·조회 API + 정적 파일 서빙 |
| `static/index.html` | 화면 1~3 |

## 핵심 로직 요약
- **분기별 독립 판정**: 각 분기 보고서마다 CFS 조회 성공 → 연결, 실패 시 OFS + 공시원문 확인 후에만 개별. 원문에 연결재무제표가 보이는데 API가 비면 개별로 단정하지 않고 `검증 필요`.
- **당기순이익**: 연결 분기 = 지배기업 소유주 귀속 순이익, 개별 분기 = 당기순이익. 한 분기의 세 항목은 항상 같은 기준.
- **2·3분기**: 보고서의 단독 3개월 금액 우선. 없을 때만 동일 기준 누적 차감.
- **4분기**: 연간 − 3분기 누적. 3분기 누적이 같은 기준으로 없으면(예: 3Q 개별·연간 연결) 다음 해 3분기보고서의 전기 비교정보(동일 기준)를 사용하고, 그것도 없으면 `검증 필요`. 다른 기준 수치는 절대 차감하지 않음.
- **TTM**: 4개 분기가 모두 검증된 항목만 합산. 하나라도 미검증이면 TTM 미확정(0으로 표시하지 않음).
- 기준이 섞이면 `혼합(연결·개별)` + 변경 시점·주석 + 비교가능성 경고. 변경 일자·사유는 공시에서 확인될 때만 표시(현재는 같은 기간 주요사항 공시를 "참고"로만 제시).

## 알려진 한계 (실제 공시와 대조 필요)
- 개발 환경에서 외부 네트워크 접속이 불가능해 **실제 DART·KRX 페이지로는 테스트하지 못했습니다.** 스크래핑 엔드포인트·파라미터·목차 형식은 알려진 구조 기준이며 합성 HTML로만 검증했습니다. 배포 후 먼저 `diagnose.py`로 점검하고, 업무지시서 8단계(실제 공시 대조)를 수행하세요.
- 스크래핑은 표준 계정ID가 없어 **계정명 기반 매칭**입니다(API 모드보다 오탐 가능성이 큼). 비표준 계정명은 `검증 필요`로 표시됩니다.
- 웹사이트 자동 수집은 이용약관·접속 제한 정책의 영향을 받을 수 있어 요청 간격(0.4초)과 캐시를 적용했습니다. 대량·상업적 이용 전 약관 확인을 권장합니다.
- 웹 모드에서는 연결범위 변경 "참고 공시" 목록을 제공하지 않습니다.
- 계정 매칭은 표준 계정ID/계정명 기반입니다. 비표준 계정(금융업 등)은 `검증 필요`로 표시됩니다.
- 2·3분기 보고서에 단독 3개월 금액 없이 한 열만 있는 경우 그 값을 누적으로 간주합니다.
- 주석·XBRL(fnlttXbrl)에서 4분기 단독 실적을 직접 파싱하는 기능과 연결범위 변경 사유 자동 판독은 구현하지 않았습니다(`검증 필요`로 표시).
- 비12월 결산법인은 company.json의 결산월로 분기를 계산하나 실제 공시와 대조가 필요합니다.
- OpenDART 일일 호출 한도가 있습니다. 응답은 `data/dart_agent.sqlite`에 캐시됩니다.
